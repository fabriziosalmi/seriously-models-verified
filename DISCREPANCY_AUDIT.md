# Discrepancy Audit: Verified Cross-Source Benchmark Discrepancies (2021-2026)

This document is generated by `scripts/build_docs_and_pdf.py` from `data/inconsistencies_catalog.json`, which `scripts/build_forensic_analysis.py` builds from the evidence ledger `data/claims.json`. Do not edit it by hand.

## 1. Method

1. Every source document is pinned: arXiv papers by explicit version, vendor pages and system cards by a timestamped Wayback Machine capture, GitHub files by commit, HELM results by release. The SHA-256 of each file is recorded in `data/downloaded_sources_manifest.json`; `scripts/download_sources.py` refuses to re-pin a source whose bytes changed.
2. Every number is a claim in `data/claims.json`: source, physical PDF page, one or more verbatim quotes, the value, and for table cells the column index. `scripts/evidence.py` checks mechanically that each quote occurs on that page of the pinned file, that the value occurs in the first quote, and that the value sits in the stated column. A claim that fails is not used.
3. Cases are pairs of claims about the same model and benchmark. Deltas are computed, never typed. The build fails if a case's text contains a number that is not a value or quoted number of the claims it cites, or a statistic recomputed from the pinned sources.
4. Each case is assigned to exactly one class:

| Class | Definition | Counted as a discrepancy |
| :---: | :--- | :---: |
| A | Contradiction: same model, benchmark and declared protocol; different published numbers | yes |
| B | Protocol asymmetry: same model and benchmark; different disclosed protocols | yes (protocol effect) |
| C | Not comparable: different benchmark/test set, unestablished checkpoint identity, or unstated protocol | no (context only) |

## 5. How much can these benchmarks resolve?

A benchmark with N independent items cannot distinguish arbitrarily small differences. The table gives, for each benchmark, the score change from one item and the standard error of a score at an illustrative accuracy p under a binomial model. The last column is the smallest difference between two independently scored models that a two-sided unpaired z-test at the 5% level resolves at that p. A paired test on the same items (McNemar) needs per-item results and is usually tighter, so this column is a conservative bound, not a property of any model. N is a verified claim.

| Benchmark | N | 1 item (pts) | p | SE (pts) | 95% CI half-width (pts) | Unpaired min. difference (pts) |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| MMLU | 14,042 | 0.01 | 0.9 | 0.25 | 0.5 | 0.7 |
| MMLU-Pro | 12,032 | 0.01 | 0.8 | 0.36 | 0.71 | 1.01 |
| GSM8K | 1,319 | 0.08 | 0.95 | 0.6 | 1.18 | 1.66 |
| MATH (test) | 5,000 | 0.02 | 0.9 | 0.42 | 0.83 | 1.18 |
| HumanEval | 164 | 0.61 | 0.9 | 2.34 | 4.59 | 6.49 |
| GPQA Diamond | 198 | 0.51 | 0.8 | 2.84 | 5.57 | 7.88 |
| SWE-bench Verified | 500 | 0.2 | 0.7 | 2.05 | 4.02 | 5.68 |
| AIME (one year) | 30 | 3.33 | 0.8 | 7.3 | 14.31 | 20.24 |

Two related facts verified in the sources: Anthropic's Claude 3.7 Sonnet score is computed on a 489-task subset of SWE-bench Verified and OpenAI's o3-mini system card on a 477-task subset, each excluding tasks that do not run on the vendor's infrastructure (claims `claude37-blog.claude-37-sonnet.swebench-verified.parallel`, `o3mini-card.o3-mini-tools.swebench-verified`). Headline SWE-bench Verified scores from different vendors are therefore not always computed on the same tasks.
